# LibreOffice browser renderer

`@deepseek-ai/libreoffice-kit-browser` loads original DOC, DOCX, PPT and PPTX bytes in a dedicated Worker and draws Writer pages or normal Impress slides through LibreOfficeKit tile APIs. It does not export or parse a PDF. All page coordinates are CSS pixels at 96 DPI; `scale` controls output pixel density. Returned pixels are owned, unassociated RGBA bytes for `ImageData`.

Serve the five resources declared in `assets.json` with their original bytes and expose their URLs through `BrowserEngineAssets`. The package has no operating-system restriction. The application must provide a secure, cross-origin-isolated context (`COOP: same-origin`, `COEP: credentialless`) and a Content Security Policy permitting its engine Worker, nested pthread Workers and WebAssembly. The loader starts its pthreads from the same loader URL; the worker bundle has no external JavaScript imports.

Call `openDocument({ data, extension, assets, timeoutMs, maxArchiveEntries, maxUncompressedBytes, maxLoadedFontBytes, fontFallbacks, resolveFonts }, signal)`. The source bytes are copied before transfer. `resolveFonts(request, signal)` receives VCL font attributes and returns immutable per-face font subsets with stable content identifiers, the original `family`, and a unique registration `alias`. Every subset must preserve shaping closure for its script and the shared combining characters it needs. Pass the same resolved `fontFallbacks` groups used by the Host matcher; both adapters share the family-ordering and Fontconfig XML implementation. No production fonts are bundled. The callback runs asynchronously on the document owner; only the engine Worker blocks while receiving 1 MiB shared-memory chunks. Distinct subsets of the same face use distinct aliases; VCL selects an alias by its actual cmap coverage. Duplicate file identifiers share one MEMFS import and the byte limit counts each identifier once. Font callbacks must preserve the same bytes and alias for an identifier. Later internal-alias requests are mapped back to the original family before invoking the Host. `onMissingFonts` reports substituted families explicitly declared in DOCX/PPTX content; engine defaults and fallback candidates do not produce warnings. Binary DOC/PPT font declarations remain inside LibreOffice and have no missing-font diagnostics.

The returned document exposes `pages`, `renderTile(request, signal)` and `dispose()`. Keep tile requests near the viewport; a tile is limited to 16 megapixels to bound allocations. Tiles are serialized. Cancelling a tile discards its result and skips queued work; aborting the document lifetime or trapping the WASM module closes the entire engine. `dispose()` awaits document and office destruction plus pthread termination, with forced worker termination after a one-second shutdown handshake if the engine cannot respond. The application owns caching, scrolling, zoom controls and localized errors. Text selection, editing, links, search and slide animation are not exposed.

Build the adapter with `pnpm build:browser`. After the WASM recipe has produced and staged a verified engine, run `node scripts/build-browser.mjs --stage`; this copies its matching source and notices and writes the resource checksum manifest. Prepack verifies every resource and the WASM direct-render exports. Node PDF conversion retains its separate API and platform selection.

The portable Host API is available as `@deepseek-ai/libreoffice-kit-fonts`, without LibreOffice engine dependencies. The [independent preview candidate](../../docs/building.md) packs and qualifies these two archives without the native-platform release matrix. Pass `--fonts-archive <fonts.tgz>` instead of `--adapter-archive` to qualify that candidate.

Run `node scripts/smoke-browser.mjs --archive <browser.tgz> --adapter-archive <node-api.tgz> --output <receipt.json>` from the kit checkout after installing Playwright Chromium. The qualification loads the archived browser and Host font code, renders all four formats and mixed Arabic/Indic text, verifies delivered font coverage, cancels a tile, and checks eventual Worker termination. `--electron <executable>` uses a sandboxed desktop window with the secure `dsh-app` scheme; `--executable <chrome>` selects a local Chromium executable. Local dirty-tree receipts record `sourceDirty: true` and cannot qualify a publication.

The Worker bundles fflate, saxes and xmlchars; their notices are included under `licenses/javascript/`. The saxes 6.0.0 npm archive omits its license, so `third-party/saxes-6.0.0-LICENSE` preserves the [upstream versioned license](https://github.com/lddubeau/saxes/blob/v6.0.0/LICENSE).
